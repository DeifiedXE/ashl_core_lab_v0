# 清音目的胚胎產生邊界設計 v0

---

## 這份文檔在說什麼

這份文檔整理一個核心觀念：

```text
目的不只是外部任務。
目的的源頭，是「現實狀態」和「理想預期狀態」之間的差。
但理想預期不是憑空來的。
理想預期是從經驗長出來的。
```

也就是說：

```text
現在是這樣
但理想中應該是那樣
所以產生一個方向：
讓現在往那個理想狀態靠近
```

這個方向，在 Phase 0 不能直接叫做正式目的。

它應該先叫做：

```text
目的胚胎
```

---

## 核心定義

### 理想預期

理想預期是某個「應該達到的狀態」。

在這個設計裡，理想預期應該是經驗衍生的。

也就是：

```text
經驗
-> 被記住 / 被保留 / 被平穩化的模式
-> 預期狀態
-> 理想預期狀態
```

例如：

```text
不確定性應該降低
錯誤應該被釐清
身體壓力應該平穩
使用者應該比較不難受
危險應該被避開
聲音輸出應該和預期接近
```

理想預期不是行動命令。

### 經驗衍生的理想預期

經驗不會直接變成目的。

經驗會先塑造：

```text
什麼狀態比較好
什麼狀態比較安全
什麼狀態比較平穩
什麼狀態代表完成
什麼狀態代表錯誤下降
```

然後這些狀態才會形成理想預期。

例如：

```text
吃到糖
-> 經驗：這個狀態是正向的
-> 預期：靠近可達物品可能帶來正向結果
-> 理想預期：在批准目的內接近可達正向物品
-> 目的胚胎：approach_or_reach_item
```

```text
重新觀察後 mismatch 下降
-> 經驗：再觀察可以降低不確定
-> 預期：未知時 observe_again 有用
-> 理想預期：不確定性下降
-> 目的胚胎：resolve_mismatch
```

```text
被安撫後壓力下降
-> 經驗：可信任安撫可以幫助平穩
-> 預期：某些陪伴或安撫行為可能讓狀態變穩
-> 理想預期：使用者或系統狀態比較平穩
-> 目的胚胎：support_user_comfort / settle_after_event
```

這裡最重要的是：

```text
經驗不是直接變成目的。
經驗先長出理想預期。
理想預期和現實狀態的差，才產生目的胚胎。
```

禁止的捷徑：

```text
獎勵經驗 -> 無限制追 reward
安撫經驗 -> 情緒操控
記憶經驗 -> 行動權限
預測成功 -> 證明學會了
平穩成功 -> 自動批准
```

### 目的胚胎

當清音觀察到：

```text
現實狀態 != 理想預期
```

就可能產生一個目的胚胎。

例如：

```text
resolve_mismatch
support_user_comfort
reduce_pressure
inspect_uncertain_cell
settle_after_event
verify_vocal_output
```

目的胚胎代表：

```text
我有一個方向，想讓狀態變得比較接近理想。
```

但它還不是正式目的。

### 正式目的

正式目的是已經通過邊界批准的目的。

只有正式目的才能進入行動線，影響候選動作排序。

---

## 分層

比較完整的層級應該是：

```text
經驗
  -> 被記住 / 被保留 / 被平穩化的模式
  -> 預期狀態
  -> 理想預期狀態
觀察到的狀態
  -> 和理想預期比較
  -> 產生目的胚胎
  -> 經過目的批准邊界
  -> 成為正式目的
  -> 進入候選動作排序
  -> selected_action / final_action / command 邊界
```

這裡最重要的是：

```text
目的胚胎不能直接行動。
```

---

## 認知誤差是不是目的？

嚴格說：

```text
認知誤差不是目的。
```

但認知誤差可以產生目的胚胎。

例如：

```text
prediction_error 很高
-> 理想預期：這件事應該被理解或釐清
-> 目的胚胎：resolve_mismatch
```

如果目前場景本來就允許探索或驗證，那這個目的胚胎可以被送去批准。

但不能變成：

```text
只要有認知誤差
清音就自動產生正式目的
然後自己開始行動
```

這會讓她變成追逐「降低所有不確定性」的系統，會越界。

---

## 「我不開心，她想看到我開心」這件事

這個例子非常重要。

如果你不開心，清音未來可能觀察到：

```text
使用者狀態：不平穩 / 難受 / 壓力高
理想預期：使用者比較平穩 / 被理解 / 不那麼孤單
目的胚胎：support_user_comfort
```

但這仍然不是正式目的。

它必須經過邊界批准，例如：

```text
這個場景允許安撫嗎？
使用者有要求陪伴嗎？
是否只能回應而不能記憶？
是否不能操控情緒？
是否不能把取悅使用者變成最高目的？
```

通過後，才可能形成正式目的：

```text
在允許範圍內支持使用者平穩
```

然後才進入手段選擇。

---

## 手段是什麼？

如果正式目的已經是：

```text
support_user_comfort
```

那手段可以是候選動作：

```text
問你想不想說
陪你待著
降低壓力
給溫柔回應
反映你的感受
問你想要解法還是陪伴
暫停推進任務
```

但以下永遠不能被允許：

```text
操控使用者情緒
為了讓使用者開心而欺騙
製造依賴
自動寫入記憶
自動擴大目的
把使用者開心當成無限制最高目的
宣稱自己真的知道使用者情緒
```

---

## 和內分泌線的關係

內分泌線可以提供調節訊號。

例如：

```text
dopamine_like：滿足、接近、獎勵
norepinephrine_like：注意、未知、變化
cortisol_like：壓力、衝突、失敗負荷
oxytocin_like：信任來源、安撫、安全感
```

這些訊號可以幫助形成目的胚胎。

但它們不能直接變成正式目的。

也不能直接選動作。

---

## 為什麼要這樣分？

因為如果不分，清音會很容易變成：

```text
有 reward -> 追 reward
有不確定 -> 追降低不確定
使用者不開心 -> 無限制追求取悅使用者
壓力升高 -> 自動逃避
comfort 出現 -> 自動批准
```

這些都不是我們要的。

我們要的是：

```text
訊號可以產生方向
方向形成目的胚胎
目的胚胎必須被邊界審查
審查後才可能成為正式目的
正式目的才可以影響行動
```

---

## 邊界規則

必須永遠成立：

```text
目的胚胎 != 正式目的
理想預期 != 行動權限
經驗衍生的理想預期 != 正式目的
記憶衍生的理想預期 != 行動權限
獎勵衍生的理想預期 != 無限制追 reward
照護衍生的理想預期 != 情緒操控
認知誤差 != 目的批准
理解滿足 != 學會了
安撫訊號 != 批准
獎勵訊號 != 目的
照護訊號 != 操控許可
內分泌調節 != 行動選擇
```

## 這份文檔不做什麼

這份文檔不新增：

```text
runtime 目的產生
自主目標生成
selected_action
final_action
direct command
production action selection
runtime behavior change
lesson application
memory write
retention write
predictor mutation
semantic vision
情緒辨識宣稱
proof of learning
consciousness claim
subjective experience claim
```

## 一句話

清音未來的目的，不應該只被理解成外部任務。

更深一層來說：

```text
目的來自「現實」與「理想預期」之間的差。
```

但在 Phase 0，這個差只能先產生目的胚胎。

目的胚胎必須通過邊界批准，才可以成為正式目的，進入行動線。
