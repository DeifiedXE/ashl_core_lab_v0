# Grounded Anonymous Auditory Event Concept Formation v0

Status: Completed by Package 130

Package 130 forms one teacher-reviewed anonymous auditory event concept from
seven fresh real Windows WASAPI loopback grounding episodes. It reuses the
Package 121 observed/expected `AudioPrimitiveRecord` schema, Package 124A
temporal records, the Package 90-92 reviewed-learning path, and Package 120A
auditable raw-audio deletion.

It does not recognize a new sound. Package 131 remains required before a new
ephemeral observation may be compared with this model.

## Grounding Corpus

The official corpus contains four positive examples and three contrast
examples. Every episode has its own audio capture session, host-state sampling
session, observation window, raw artifact, primitive, and trace lineage. Set A
and Set B run in different operating-system processes and have different
grounding-run identities while preserving one verified endpoint, capture
configuration, compiler version, and blur-policy version.

Positive and contrast membership is an explicit local-teacher assignment. The
fixture manifest becomes available only after each observed primitive and
feature projection are frozen. Candidate generation, expected primitives, and
predictive validation never consume fixture timing, frequency, or role data.

## Source Blur

The retained projection contains low-level event structure only:

- median active-region envelope shape after each region is normalized; one
  detector-boundary bin is removed from each side before resampling so WASAPI
  chunk-edge ramps do not become concept identity
- onset and offset counts
- normalized active-region duration ratios
- normalized inter-onset interval ratios
- silence ratio
- rank-ordered relative spectral-energy shape

Absolute gain is normalized. Spectral band position and exact pitch identity
are not retained; `coarse_pitch_contour` is `null` in v0 because the current
compiler contour is not sufficiently source-blurred for this concept scope.
No reversible waveform, transcript, speaker embedding, semantic label, object
identity, action identity, material identity, or emotion meaning is created.

## Predictive Validation

The expected `AudioPrimitiveRecord` is generated by deterministic coordinate
medians over positive projections. Tolerances are the maximum observed
positive deviation plus fixed, recorded per-feature margins. Validation runs
four leave-one-positive-out checks and tests all three contrasts against the
full positive template.

Every feature error and tolerance check remains visible. There is no weighted
confidence score. Any held-out positive outside its structural tolerances or
any contrast inside all tolerances blocks teacher review.

## Teacher And Memory Boundary

The candidate stops at the existing exact teacher gate. Approval binds the
candidate, source profile, all seven episodes, all projections, expected
primitive, predictive validation, maturity record, compiler, blur policy, and
evidence identity.

Approval creates the existing `ReviewedConcept`, `MemoryLearningTrace`,
`MemoryRoutingTrace`, and `MemoryApplicationData`. Routing targets the archive
and the typed consumer scope is:

`package_131_auditory_prediction_only`

No active Package 112 working readback is created. Reject creates no model and
deletes grounding waveforms after preserving primitive traces. Defer creates no
model and cannot extend the original grounding lease.

## Model And Deletion Gate

The stable concept identity has this form:

`auditory_event_concept:<sha256>`

It is a technical content identity, not a word or CL token. Before deletion the
append-only model state is `reviewed_waiting_raw_audio_cleanup` and both
Package 131 consumption and runtime recognition are disabled.

All seven grounding waveforms are then deleted through Package 120A. Artifact
IDs, pre-deletion content hashes, deletion records, primitive records, contrast
records, and trace references remain. Only after zero raw blobs and no
recoverable waveform are verified is a second append-only state written as
`reviewed_grounded_ready_for_package_131`. The stable concept identity does not
change, Package 112 influence remains disabled, and recognition remains false.

## CLI

Set A and Set B commands each spawn an isolated worker process:

```text
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli preflight --state-dir <path> --render-endpoint default
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli run-grounding-set-a --state-dir <path> --render-endpoint default --allow-grounding-capture
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli run-grounding-set-b --state-dir <path> --render-endpoint default --allow-grounding-capture
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli show-episodes --state-dir <path>
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli assign-grounding-examples --state-dir <path> --positive <ids> --contrast <ids> --confirm
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli build-concept-candidate --state-dir <path>
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli show-teacher-review --state-dir <path>
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli review-concept --state-dir <path> --decision approve --reviewer local_teacher --expected-evidence-identity <hash> --confirm
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli delete-grounding-audio --state-dir <path> --confirm
py -3 -m ashl_core_v1.runtime.package_130_auditory_concept_cli audit --state-dir <path>
```

`guided-run` advances one explicit boundary at a time. It does not infer the
teacher assignment, approve the candidate, or delete data without the required
command and confirmation.

## Boundaries And Roadmap

Package 130 creates no runtime recognition, auditory prediction loop, speaker
profile, transcript, semantic meaning, internal action, output, external
control, GCMC/CL runtime, D-Laplace component, or DLM-1 implementation.

Package 131 Auditory Predictive Recognition is next. Package 132 then closes
perception capability construction. DLM-1 and Package 133 remain after Package
132; no additional perception package is inserted.
