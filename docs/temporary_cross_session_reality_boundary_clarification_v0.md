# Temporary Cross-Session Reality Boundary Clarification v0

## Purpose

Clarify that cross-session in v0 means controlled demo handoff, not durable persistence.

## Boundary

- `temporary_cross_session_experience_space` is not memory.
- `temporary_cross_session_experience_space` is not history runtime.
- `temporary_cross_session_experience_space` is not lesson retention.
- `temporary_cross_session_experience_space` is not durable across process restart.
- `temporary_cross_session_experience_space` must be deprecated or bypassed after future four-layer memory exists.

## Reality Model

In v0, cross-session means controlled demo/fixture handoff only. It may pass not_retained experience candidates across simulated session contexts inside deterministic checks, but it does not create durable storage or a memory system.

Any future durable persistence requires a separate persistence boundary review and implementation package.

## Explicitly Not Implemented

- Durable persistence.
- File-backed memory or database storage.
- Real memory read or memory write.
- History runtime.
- Lesson retention or lesson application.
- Action selection influence or behavior change.
- Predictor mutation.
- Proof-of-learning claim.
